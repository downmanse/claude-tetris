## 1. 프로젝트 개요

### 1.1 한 줄 소개
Python으로 구현하는 클래식 테트리스 게임으로, 표준 테트리스 규칙(SRS 회전, 7-bag 랜덤, 홀드/넥스트)을 충실히 재현하고 로컬 랭킹 시스템으로 반복 플레이의 동기를 부여하는 싱글플레이어 퍼즐 게임.

### 1.2 장르
- 낙하형 퍼즐 게임(Falling Block Puzzle) / 아케이드

### 1.3 타겟 플랫폼
- Windows/macOS/Linux PC, 로컬 실행 전용(설치형 또는 단일 실행 파일)
- 온라인 서버, 멀티플레이, 모바일 대응은 본 프로젝트 범위 외

### 1.4 타겟 사용자층
- 테트리스 클래식 규칙(가이드라인 표준)에 익숙한 20~40대 캐주얼/코어 퍼즐 게임 유저
- 개인 최고 점수 갱신과 로컬 순위 경쟁에서 재미를 느끼는 솔로 플레이어
- Python 학습자/개발자가 참고용으로 플레이하거나 코드를 분석하는 경우도 부차적으로 고려

### 1.5 핵심 매력(USP)
1. **정확한 클래식 규칙 재현**: SRS(Super Rotation System) 기반 회전, 7-bag 랜덤 시스템, 홀드 기능 등 실제 가이드라인 테트리스에 가까운 손맛을 제공.
2. **가벼운 로컬 랭킹**: 온라인 서버 없이도 로컬 SQLite/파일 기반으로 개인 최고 기록과 역대 Top 10을 즉시 확인 가능해, 반복 플레이의 동기를 부여.
3. **가벼운 설치/실행**: Python + pygame 기반의 단일 실행 파일(exe)로 배포되어, 별도 설치 없이 즉시 실행 가능.

## 2. 핵심 기능 목록

### 2.1 테트로미노 낙하 시스템

**목적**: 게임의 기본 루프인 "블록이 위에서 아래로 자동 낙하하며 플레이어가 조작할 시간"을 제공한다.

**동작 방식**:
- 7종 테트로미노(I, O, T, S, Z, J, L)를 표준 색상(청록 I, 노랑 O, 보라 T, 초록 S, 빨강 Z, 파랑 J, 주황 L)으로 표시.
- 낙하 속도는 레벨에 따라 결정되며, 아래 공식(가이드라인 표준 근사치)을 사용:
  - `frames_per_gridcell = (0.8 - ((level - 1) * 0.007))^(level - 1)` (초당 60프레임 기준)
  - 단, 구현 편의를 위해 레벨별 낙하 간격(초)을 룩업 테이블로 미리 정의하여 사용(레벨 0~19까지 세분화, 레벨 20 이상은 최저 간격 0.05초로 고정, 이른바 "20G" 근처 속도).
  - 예: 레벨 1 = 1.0초/칸, 레벨 5 = 0.5초/칸, 레벨 10 = 0.2초/칸, 레벨 15 = 0.1초/칸, 레벨 20 이상 = 0.05초/칸.
- **소프트 드롭(Soft Drop)**: 아래 방향키를 누르는 동안 낙하 속도를 20배로 가속(최대치는 프레임당 1칸으로 캡).
- **하드 드롭(Hard Drop)**: 스페이스바 입력 시 즉시 바닥(또는 착지 지점)까지 이동시키고 즉시 고정(lock). 하드 드롭 사용 칸 수만큼 보너스 점수 부여(2점/칸).
- **락 다운(Lock Down)**: 블록이 바닥이나 다른 블록에 닿은 후 0.5초(Lock Delay) 동안 이동/회전이 가능하며, 그 사이 이동/회전을 하면 타이머가 리셋(최대 리셋 횟수 15회, 이후 강제 고정)되는 클래식 테트리스 가이드라인 방식(Extended Placement Lockdown 간소화 버전) 적용.

**UI/UX 요소**:
- 메인 플레이필드: 10열 × 20행 그리드(위쪽 여분 2줄은 화면 밖에 숨김 처리, 총 22행 내부 관리).
- 낙하 중 블록은 그림자(Ghost Piece)로 착지 예상 위치를 반투명하게 표시(옵션으로 ON/OFF 가능).

### 2.2 테트로미노 이동 및 회전(SRS)

**목적**: 플레이어가 블록을 원하는 위치/방향으로 배치할 수 있도록 정밀한 조작감을 제공.

**동작 방식**:
- **이동**: 좌/우 방향키로 1칸씩 이동. 키를 누르고 있으면 초기 지연(DAS, Delayed Auto Shift) 0.3초 후 반복 이동(ARR, Auto Repeat Rate) 0.05초 간격으로 자동 이동.
- **회전**: 상 방향키 또는 X키(시계방향), Z키(반시계방향)로 90도 단위 회전. **SRS(Super Rotation System)** 표준 킥 테이블 적용:
  - 각 테트로미노(I 제외)는 5개의 회전 상태별 킥 오프셋 테이블을 사용하여, 벽/다른 블록에 막혔을 때 자동으로 위치를 보정(Wall Kick)하여 회전을 시도.
  - I 블록은 별도의 확장 킥 테이블(더 넓은 킥 범위) 사용.
  - O 블록은 회전해도 형태가 동일하므로 킥 테이블 불필요(제자리 회전).
  - T-스핀(T-Spin) 판정 로직 포함: T블록이 3개 코너가 막힌 상태에서 킥을 이용해 회전 성공 시 T-스핀으로 판정하여 점수 보너스 부여(§2.3 참고).
- **하드 드롭/소프트 드롭**: §2.1 참고.

**UI/UX 요소**:
- 키 입력 즉시 반응(입력 지연 1프레임 이내 목표).
- 회전 실패 시 시각적 피드백 없음(자연스러운 무반응), 회전 성공 시 즉각적인 블록 이동으로 피드백.
- 조작키 안내는 옵션 메뉴 및 일시정지 화면에 상시 노출.

### 2.3 줄 삭제 및 점수 계산

**목적**: 플레이어의 목표(줄 삭제)를 명확히 하고, 전략적 플레이(테트리스, T-스핀 등)에 대한 보상을 제공하여 몰입도를 높인다.

**동작 방식**:
- 한 행이 10칸 모두 채워지면 해당 행 삭제, 위쪽 블록들이 한 칸씩 아래로 이동.
- 동시 삭제 줄 수에 따라 명칭과 점수가 다름(가이드라인 표준 점수표, 레벨 배수 적용):

| 삭제 유형 | 줄 수 | 기본 점수(레벨 1 기준) | 점수 공식 |
|---|---|---|---|
| Single | 1줄 | 100 | 100 × level |
| Double | 2줄 | 300 | 300 × level |
| Triple | 3줄 | 500 | 500 × level |
| Tetris | 4줄 | 800 | 800 × level |
| T-Spin Single | 1줄(T스핀) | 800 | 800 × level |
| T-Spin Double | 2줄(T스핀) | 1200 | 1200 × level |
| T-Spin Triple | 3줄(T스핀) | 1600 | 1600 × level |

- **소프트/하드 드롭 보너스**: 소프트 드롭 1칸당 1점, 하드 드롭 1칸당 2점(레벨 무관, 고정).
- **콤보(Combo)**: 연속으로 줄을 삭제할 때마다 콤보 카운트 증가, 콤보당 `50 × combo_count × level` 추가 점수.
- **백투백(Back-to-Back)**: 테트리스 또는 T-스핀 삭제가 연속으로 발생하면 1.5배 점수 보너스.
- **퍼펙트 클리어(All Clear)**: 필드의 모든 블록이 삭제되면 추가 보너스(예: 2000 × level).

**UI/UX 요소**:
- 줄 삭제 시 해당 행 짧은 플래시 애니메이션(0.2초) 후 삭제.
- 화면 우측 상단에 현재 점수, 삭제 유형 텍스트("TETRIS!", "T-SPIN DOUBLE!" 등)를 0.8초간 팝업 표시.
- 콤보/백투백 카운터를 사이드 패널에 상시 표시.

### 2.4 레벨 및 속도 시스템

**목적**: 시간이 지날수록 난이도를 상승시켜 긴장감을 유지하고, 실력 향상에 따른 성취감을 제공.

**동작 방식**:
- 레벨은 1부터 시작(옵션 메뉴에서 시작 레벨을 1~15 중 선택 가능).
- **레벨업 조건**: 누적 삭제 줄 수가 `level × 10` 줄에 도달하면 레벨이 1 상승. (예: 레벨 1→2는 10줄, 레벨 2→3은 20줄 누적... 가이드라인의 "10 lines per level" 방식)
- 레벨 상승 시 §2.1의 낙하 속도 테이블에 따라 즉시 속도 증가.
- 레벨 상한은 20으로 설정하고, 20 이상은 속도 고정(최저 낙하 간격 0.05초/칸)하되 레벨 표시는 계속 증가시켜 점수 배율에는 반영.

**UI/UX 요소**:
- 화면 좌측 상단에 "LEVEL: N" 상시 표시.
- 레벨업 순간 화면 중앙에 "LEVEL UP!" 텍스트 0.5초간 표시 + 사운드 효과.
- 현재 레벨에서 다음 레벨까지 필요한 줄 수를 프로그레스 바로 시각화.

### 2.5 홀드 및 다음 블록 미리보기

**목적**: 전략적 플레이(현재 블록을 보류하고 다른 블록 먼저 사용)를 가능하게 하고, 다음에 올 블록을 예측해 배치 계획을 세울 수 있게 한다.

**동작 방식**:
- **홀드(Hold)**: C키 입력 시 현재 조작 중인 블록을 홀드 슬롯에 저장하고, 저장되어 있던 블록(있다면)을 대신 낙하시킴. 홀드 슬롯이 비어있으면 다음 큐에서 블록을 가져옴.
- 홀드는 새 블록이 생성된 직후부터 고정(lock)되기 전까지 1회만 사용 가능(고정 후 다시 사용 가능하도록 리셋).
- **넥스트 큐(Next Queue)**: 다음에 등장할 블록 5개를 미리 보여줌.
- **7-bag 랜덤 시스템**: 7종 블록을 한 세트(bag)로 묶어 무작위로 섞은 뒤 순서대로 소진, 소진되면 새로운 bag을 생성하여 큐에 추가. 이를 통해 같은 블록이 연속으로 나오지 않도록(최대 12개 블록 이내 재출현 보장) 공정한 랜덤성 제공.

**UI/UX 요소**:
- 화면 좌측에 홀드 슬롯(블록 미니어처 표시), 사용 불가 상태일 때는 반투명 처리.
- 화면 우측에 다음 5개 블록을 세로로 나열한 넥스트 패널.

### 2.6 게임 오버 조건

**목적**: 게임의 종료 시점을 명확히 정의하여 플레이 세션을 마무리하고 결과(점수)를 확정한다.

**동작 방식**:
- **블록 오버플로우(Lock Out / Block Out)**: 새로 생성된 블록이 생성 즉시 다른 블록과 겹쳐서 배치할 수 없는 경우 즉시 게임 오버.
- **탑 아웃(Top Out)**: 고정된 블록이 화면에 보이는 플레이필드(20행) 위쪽 스킵존을 지속적으로 침범하여 신규 블록이 정상적으로 생성될 공간이 없는 경우 게임 오버.
- 게임 오버 시 낙하/입력 즉시 중단, 최종 점수/레벨/삭제 줄 수/플레이 시간 집계.

**UI/UX 요소**:
- 화면 중앙에 "GAME OVER" 텍스트와 최종 통계(점수, 레벨, 라인, 시간) 표시.
- 곧바로 랭킹 시스템(§2.7)의 이름 입력 화면으로 자연스럽게 전환.
- "다시 시작" / "메인 메뉴로" 버튼 제공.

### 2.7 랭킹 시스템

**목적**: 반복 플레이의 동기를 부여하고, 로컬 환경에서 플레이어 간(또는 자기 자신과의) 점수 경쟁 요소를 제공.

**동작 방식**:
- 게임 오버 시 최종 점수가 로컬 저장된 Top 10 기록에 포함될 만큼 높으면(즉, Top 10 최저 점수보다 높거나 기록이 10개 미만이면) 이름 입력 화면 표시.
- **이름 입력**: 최대 8자 영문/숫자(또는 한글 3자) 입력, 온스크린 키보드 또는 물리 키보드 입력 지원. 입력 없이 일정 시간(10초) 경과 시 "PLAYER"로 자동 저장.
- **저장 데이터**: 이름, 점수, 레벨, 삭제 줄 수, 플레이 날짜/시각(ISO 8601 형식), 플레이 시간(초).
- **랭킹 조회**: 메인 메뉴에서 "랭킹 보기" 선택 시 Top 10을 점수 내림차순으로 표시. 동점자는 먼저 기록된 순서(날짜/시각) 기준으로 정렬.
- **정렬 옵션**(2차 개발 고려): 최고 점수순 / 최근 플레이순 필터 전환 가능.
- 랭킹 데이터는 게임 재설치/재실행 시에도 유지되도록 사용자 로컬 디렉토리(예: `%APPDATA%/Tetris/ranking.db` 또는 실행 파일 인접 폴더)에 영구 저장.

**UI/UX 요소**:
- 이름 입력 화면: 텍스트 입력 필드 + 현재 점수가 몇 위에 해당하는지 실시간 미리보기("현재 3위!").
- 랭킹 화면: 순위(1~10), 이름, 점수, 레벨, 날짜를 테이블 형태로 표시. 신규 갱신된 항목은 강조 색상(예: 금색 하이라이트)으로 표시.
- 메인 메뉴에 "랭킹" 버튼 상시 노출.

## 3. 사용자 시나리오

### 3.1 시나리오 A: 신규 유저 온보딩

1. 유저가 실행 파일(`Tetris.exe`)을 더블클릭하여 게임을 실행한다.
2. 메인 메뉴 화면이 표시되고, "시작", "랭킹", "설정", "종료" 4개 버튼이 보인다.
3. 처음 실행이므로 랭킹 데이터베이스가 비어있어 "랭킹" 진입 시 "아직 기록이 없습니다. 첫 기록의 주인공이 되어보세요!" 안내 문구가 표시된다.
4. 유저가 "설정"에서 조작키 안내(방향키: 이동, 위/X: 회전, Z: 반시계 회전, 스페이스: 하드 드롭, C: 홀드, ESC: 일시정지)를 확인한다.
5. "시작"을 눌러 시작 레벨(기본값 1)로 게임을 시작한다.
6. 낙하하는 블록을 조작하며 첫 줄을 삭제하는 데 성공, 화면에 "SINGLE! +100" 팝업이 표시된다.
7. 레벨 1에서 10줄을 채우자 "LEVEL UP!" 애니메이션과 함께 레벨 2로 상승, 낙하 속도가 눈에 띄게 빨라진다.
8. 실수로 블록을 쌓다가 상단까지 채워져 게임 오버가 발생한다.
9. 게임 오버 화면에서 최종 점수(예: 3,450점)와 함께 "신기록입니다! 이름을 입력하세요"라는 메시지가 표시된다(첫 기록이므로 자동으로 Top 1위).
10. 유저가 이름("KIM")을 입력하고 확인을 누르면 랭킹 화면으로 이동하여 자신의 이름이 1위에 등록된 것을 확인한다.
11. "다시 시작" 버튼을 눌러 재도전하거나, 메인 메뉴로 돌아간다.

### 3.2 시나리오 B: 숙련 유저의 반복 플레이 및 랭킹 갱신

1. 기존에 여러 번 플레이하여 랭킹에 3개의 기록(1위 15,000점, 2위 12,000점, 3위 9,500점)을 보유한 숙련 유저가 게임을 실행한다.
2. 메인 메뉴에서 "랭킹"을 눌러 현재 Top 10 순위를 확인하고 자신의 최고 기록(15,000점)을 다시 상기한다.
3. "설정"에서 시작 레벨을 5로 상향 조정하여 더 빠른 속도에서 도전하기로 결정한다.
4. "시작"을 눌러 게임에 진입, 홀드 기능과 넥스트 큐 예측을 적극 활용하여 테트리스(4줄 동시 삭제)를 연속으로 성공시킨다.
5. 백투백 테트리스 보너스가 누적되며 점수가 빠르게 상승, 화면에 "TETRIS!" "BACK-TO-BACK!" 팝업이 연이어 표시된다.
6. T-스핀 트리플까지 성공시키며 점수를 16,200점까지 끌어올린 후, 게임 오버가 발생한다.
7. 게임 오버 화면에서 "신기록! 현재 1위입니다!" 메시지가 표시되고, 이름 입력 화면으로 전환된다.
8. 이름("PRO_KIM")을 입력하고 저장하면, 기존 1위(15,000점)를 밀어내고 자신이 새로운 1위에 등록된 것을 랭킹 화면에서 확인한다.
9. 기존 3위 기록(9,500점)은 순위 밖(4위)으로 밀려나 Top 10에는 계속 남아있음을 확인한다(Top 10 유지 정책).
10. 만족한 유저는 "메인 메뉴로" 돌아가 게임을 종료하거나, 다시 도전을 이어간다.

## 4. 기술 스택

### 4.1 클라이언트(게임 엔진/라이브러리)

| 구분 | 선택 | 이유 |
|---|---|---|
| 언어 | Python 3.11+ | 콘셉트 요구사항, 빠른 프로토타이핑, 1인 개발에 적합한 생산성 |
| 게임 프레임워크 | **pygame (pygame-ce 권장)** | 2D 그리드 기반 게임에 최적화, 방대한 커뮤니티/문서, 사운드/입력/렌더링을 단일 라이브러리로 처리 가능. pygame-ce는 유지보수가 활발하여 원조 pygame보다 권장 |
| 대안 검토(미채택) | Arcade, Pyglet | pygame 대비 학습 자료가 적고, 이번 프로젝트 규모(단순 2D 그리드)에는 과한 기능(3D, 셰이더 등) 포함. 채택하지 않음 |
| 프레임 관리 | pygame.time.Clock, 고정 60FPS 목표 | 낙하 타이밍/입력 반응성의 일관성 확보(딜타타임 기반 로직으로 프레임 드랍에도 안정적 타이밍 유지) |
| 사운드 | pygame.mixer | 블록 회전/고정/줄 삭제/레벨업 등 짧은 SFX 재생에 충분 |

### 4.2 랭킹 데이터 저장 방식

**선택: SQLite (Python 표준 라이브러리 `sqlite3`)**

| 비교 항목 | 로컬 파일(JSON/CSV) | SQLite |
|---|---|---|
| 동시성/무결성 | 수동 처리 필요(쓰기 중 크래시 시 손상 위험) | 트랜잭션 지원으로 안전 |
| 정렬/조회 | 매번 전체 로드 후 정렬 필요 | `ORDER BY score DESC LIMIT 10` 등 SQL로 간결 처리 |
| 확장성 | 필드 추가 시 마이그레이션 번거로움 | 스키마 변경 용이(ALTER TABLE), 향후 통계 기능 확장에 유리 |
| 구현 난이도 | 매우 낮음 | 낮음(표준 라이브러리 내장, 외부 의존성 없음) |
| 결론 | - | **채택**: 표준 라이브러리라 추가 설치 불필요, 소규모지만 데이터 안정성과 향후 확장성(예: 통계 화면 추가) 모두 확보 |

- 저장 경로: `%APPDATA%/PyTetris/ranking.db`(Windows) 또는 `~/.pytetris/ranking.db`(macOS/Linux), `appdirs` 또는 `platformdirs` 패키지로 OS별 경로 처리.
- 테이블 스키마(예시):
  ```sql
  CREATE TABLE IF NOT EXISTS ranking (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      player_name TEXT NOT NULL,
      score INTEGER NOT NULL,
      level INTEGER NOT NULL,
      lines_cleared INTEGER NOT NULL,
      play_time_seconds INTEGER NOT NULL,
      played_at TEXT NOT NULL
  );
  ```
- 손상 대비: 앱 시작 시 DB 파일 무결성 체크(`PRAGMA integrity_check`) 실패 시 백업 후 신규 생성.

### 4.3 배포 방식

- **PyInstaller**를 사용하여 `--onefile` 옵션으로 단일 실행 파일(exe) 패키징.
  - 이유: 1인/소규모 프로젝트 특성상 사용자가 Python 환경을 설치하지 않고도 즉시 실행할 수 있어야 함. PyInstaller는 pygame 프로젝트와의 호환성이 검증되어 있고 커뮤니티 자료가 풍부함.
- 리소스(폰트, 이미지, 사운드)는 `--add-data` 옵션으로 실행 파일에 포함, 실행 시 임시 디렉토리(`sys._MEIPASS`)에서 로드하도록 경로 처리.
- 랭킹 DB는 실행 파일 내부가 아닌 사용자 로컬 디렉토리(§4.2)에 별도 저장하여, 재설치/업데이트 시에도 기록 유지.
- Windows 우선 배포, macOS/Linux는 소스 실행(Python + pygame 설치) 방식으로 대체 지원(추후 개발 단계에서 각 OS별 패키징 검토).

### 4.4 프로젝트 구조 제안(참고용)

## 5. 개발 우선순위

### 5.1 MVP (최소 기능 제품)

**목표**: "플레이 가능한 클래식 테트리스 한 판"을 완성하여 핵심 재미를 검증.

| 기능 | 근거 |
|---|---|
| 테트로미노 낙하/이동/기본 회전(단순 회전, SRS 킥 미포함 초기 버전 가능) | 게임의 최소 성립 조건 |
| 줄 삭제 및 기본 점수 계산(Single/Double/Triple/Tetris) | 핵심 게임 루프 완성에 필수 |
| 레벨/속도 시스템 | 난이도 곡선 없이는 게임이 지루해짐, MVP에서도 최소한의 긴장감 필요 |
| 넥스트 블록 미리보기(1개 이상) | 최소한의 전략적 판단 요소 없이는 테트리스라 부르기 어려움 |
| 게임 오버 조건 및 재시작 | 플레이 세션의 시작/끝이 명확해야 함 |
| 랭킹 시스템(기본: 로컬 저장, Top 10 조회, 이름 입력) | 콘셉트의 핵심 요구사항이며, 반복 플레이 동기부여의 핵심 |
| 기본 UI(점수/레벨/줄 수 표시, 일시정지) | 플레이에 필수적인 정보 전달 |

**MVP 제외 사유**: SRS 완전 구현, 홀드, T-스핀 판정, 콤보/백투백 보너스, 고스트 피스, 7-bag 랜덤(초기엔 단순 랜덤으로 대체 가능)은 "핵심 루프 검증"에 필수는 아니므로 2차로 이동.

### 5.2 2차 개발

**목표**: 클래식 테트리스 가이드라인 표준에 근접한 완성도와 조작감 확보.

| 기능 | 근거 |
|---|---|
| SRS 완전 구현(킥 테이블, I블록 확장 킥) | MVP의 단순 회전은 벽/구석에서 부자연스러움이 커서, 조작감 완성도를 위해 필요하나 초기 검증에는 필수는 아님 |
| 7-bag 랜덤 시스템 | 공정한 랜덤성은 숙련 유저의 만족도에 큰 영향을 주지만, MVP 검증 단계에서는 단순 랜덤으로도 충분 |
| 홀드 기능 | 전략적 깊이를 더하는 요소로, 핵심 루프 자체보다는 플레이 편의성 향상에 해당 |
| 고스트 피스 | 조작 편의성 개선, 없어도 플레이는 가능 |
| T-스핀 판정 및 보너스 점수 | 고급 플레이 요소로 숙련자 리텐션에 기여하나 구현 복잡도가 높아 후순위 |
| 콤보/백투백 보너스 | 점수 시스템의 재미를 강화하나 기본 점수 계산이 선행되어야 함 |
| 넥스트 큐 확장(5개 미리보기) | MVP의 1개 미리보기에서 확장, 전략성 강화 |
| 랭킹 정렬 옵션(최근순 등), 통계(플레이 시간 등 상세 기록) | 부가 기능으로 핵심 경험에 직접 영향은 적음 |
| 사운드/BGM, 시작 레벨 선택 옵션 | 완성도와 몰입감을 높이는 요소 |

### 5.3 추후 개발(Nice to have)

**목표**: 완성 이후 부가적인 만족도/편의성 향상.

| 기능 | 근거 |
|---|---|
| 키 입력 커스터마이징(리바인딩) | 개인화 편의 기능, 핵심 경험과 무관 |
| 다양한 테마/스킨(블록 색상, 배경) | 시각적 다양성, 재플레이 유인이지만 우선순위 낮음 |
| macOS/Linux 네이티브 패키징 | 초기 타겟은 Windows 중심, 추가 플랫폼은 수요 확인 후 진행 |
| 리플레이 저장/재생 기능 | 구현 복잡도가 높고 핵심 유저층 요구가 명확히 확인된 이후 고려 |
| 통계 대시보드(누적 플레이 시간, 평균 점수 등 그래프) | 데이터는 이미 SQLite에 축적되므로 기술적 진입장벽은 낮으나, 부가 기능으로 후순위 |
| 난이도 프리셋(마라톤/스프린트/울트라 모드) | 클래식 마라톤 모드 외 추가 모드는 콘셉트 확장이므로 충분한 검증 후 검토 |
